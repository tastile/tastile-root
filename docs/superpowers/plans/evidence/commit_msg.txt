fix(v1): emit one Flow placement per GAP + clip span to proposal baseline

Two related fixes to flow_tick::evaluate_window so the v1-schedule-packing
goal-mode curl/seed evidence matches the spec (one source=Flow Placement
per qualifying Gap, sized to the proposal when it fits, fallback-sized
otherwise):

  - Drop the break that exited the inner `for gap in gaps` loop after
    the FIRST dispatch.  The intent comment said "one Placement per
    (Flow x Candidate x GAP)" but the break prevented that for windows
    with 2+ gaps: previously only the first gap was packed.  Removing
    it iterates every qualifying gap and emits one Placement per GAP,
    keyed by proposal_key = flow:candidate:plan:gap_start_ms
    (AT-027 idempotency).

  - Replace the single-endpoint `gap.end.min(proposal.baseline.span.end)`
    with a full clip of the proposal baseline span against the gap:
        p_start = max(proposal.baseline.span.start, gap.start)
        p_end   = min(proposal.baseline.span.end, gap.end)
        if p_end > p_start: emit clipped proposal
        else:              emit (gap.start, gap.start + min(dur, gap.size))

    AT-028 wants a 10:00-10:30 Placement in the gap to A's end and B's
    start: proposal.start=10:00, proposal.end=10:30, gap=(10:00, 10:30)
    -> p_start=10:00, p_end=10:30 -> emit (10:00, 10:30).
    For a wider Gap like (08:00, 09:00) where the proposal does not fit
    (p_end=min(10:30,09:00) < p_start=max(10:00,08:00)) -> fall back to
    a 30-min slice starting at gap.start -> (08:00, 08:30).

Endpoint (crates/v1/api/src/handlers/timeline.rs): make the owner-profile
fetch fault-tolerant when the v1/15-migrated v1_owner table is absent.
Goal CONSTRAINT 1 forbids adding the migration; degrade to empty owner
profiles instead of 500.  TimelineItem.owner is already
Option<TimelineOwnerEmbed> so the response shape is unchanged when the
embed is absent.
