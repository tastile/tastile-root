# 依存パッケージ bump 計画 (2026-09-05)

> **For agentic workers:** 必須サブスキル: `superpowers:subagent-driven-development` (推奨) または `superpowers:executing-plans` を使用し、本計画をリポジトリ単位 / bump 単位に分解して実装する。各ステップはチェックボックス (`- [ ]`) 形式で進捗追跡する。

**Goal:** `tastile-web` / `tastile-core` / `tastile-android` / `tastile-desktop` の pinned 依存を最新 stable へ bump する。patch / minor / major すべてを対象とする。各 repo の CI / workspace gate を全て Green に収束させる。

**Scope agreement (2026-09-05):**
- 全 repo を対象: `tastile-web` (Bun/npm) / `tastile-core` (Cargo, **crates-v1 のみ**) / `tastile-android` (Gradle Kotlin DSL) / `tastile-desktop` (NuGet)
- bump level: patch + minor + major すべて許可。major 破壊変更は同一 PR 内で config migration まで含めて完了
- 実行手順: 本 Plan doc を 1 commit で先行し、合意後に実装着手

## 不変条件 (全 repo 共通)

- **`@latest` auto-pull 禁止 (ADR-0001)**: `bun update --latest` / `cargo update --aggressive` / `gradle --refresh-dependencies` のような暗黙の最新化は禁止。必ず `package.json` / `Cargo.toml` / `build.gradle.kts` / `.csproj` を明示編集してから install / resolve
- **Plan→Implement 2 段 (AGENTS.md §3-1)**: 本 doc を 1 commit (`chore(plan): add 2026-09-05 deps bump plan`) に閉じ、その後実装に着手
- **drift の record**: bump した version は ADR ではなく `docs/kiban/deps-bump-log-2026-09-05.md` (本 commit 同時作成) に付録として残す。policy §30 (audit 結果の screenshot/log を commit しない) と整合させるため、`.tmp/` で組み立てて確定版のみ docs/ へ移す
- **security advisory 放置禁止 (plugin-version-audit SKILL.md)**: `bun audit` / `cargo audit` が advisory を返す場合、別 commit で先に潰す
- **`git status --short` 確認**: 開始時に main branch で clean。worktree は作らない (memory `feedback_no_git_worktree_default.md`)
- **他タスク由来の uncommitted diff**: `docs/plans/2026-08-25-p1-ds-token-plumbing.md` / `docs/runbooks/sops-rollback.md` 等は触らない。git status M を残したまま本タスクの作業範囲のみ edit する
- **依存追加は最小**: 新規 npm / Cargo / Gradle / NuGet package を追加しない。既存依存の最新化のみ
- **i18n hardcoded literal を新規追加しない**: comment / identifier / doc-comment はすべて英語 (AGENTS.md)
- **commit 単位**: 各 repo × bump type (patch / minor / major) で 1 commit。`feat(deps):` / `chore(deps):` / `fix(deps):` prefix。precommit-review (`.agents/skills/tastile-precommit-review`) を必ず通す
- **CI is the gate**: 全 repo の CI run が green になるまで "ship した" と述べない (memory `feedback_ci_is_the_gate.md`)

## リスク

- **Biome v1 → v2**: formatter / linter の config schema 差分が大きい。`biome.json` を手動で書き換えるか `bunx @biomejs/biome migrate` を使う
- **Vitest v4 → v5**: API breaking changes (e.g. `vi.mocked`, `pool` option)。`bun run test:unit` の出力で潰す
- **sqlx 0.8 → 0.9** (もし major bump する場合): SQL macro の互換性が崩れる可能性が高い。本 Plan では 0.8 系内 patch / minor のみに限定
- **serde 1 → 2**: ecosystem 全体の破壊的変更。Rust community でも慎重。本 Plan では 1 系内 patch / minor のみ
- **tokio 1 → 2**: API 破壊的変更。本 Plan では 1 系内 patch / minor のみ
- **AGP / Kotlin / Compose の major**: Android toolchain 全体の整合性が崩れる。本 Plan では patch + minor に限定
- **Windows App SDK の major**: WinUI API 変更。本 Plan では patch + minor に限定

## ロールバック

- **各 commit が独立して revert 可能**: bump unit を細かく刻んでいるため、1 commit = 1 repo + 1 bump type の粒度で `git revert` できる
- **`Cargo.lock` の rollback**: cargo は lock を手で書き換えるより `Cargo.toml` を旧 version に戻して `cargo update` で再生成する方が安全
- **`bun.lock` の rollback**: package.json を旧 version に戻して `bun install` で再生成
- **`gradle.lockfile` の rollback**: `.kts` を旧 version に戻して `./gradlew :app:dependencies --refresh-dependencies` で再生成
- **本 Plan の cancel**: Commit 1 のみ revert すれば本タスク自体を無かった事にできる (実装 commit は 1 件も作っていない)
