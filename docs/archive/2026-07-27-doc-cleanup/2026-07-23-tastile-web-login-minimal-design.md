# Tastile Web ログイン画面の最小化

## 1. 背景

`/login` は認証操作に加えて、マーケティング用ヘッダー、デバイス説明、補足カード、フッターまで同一画面に表示している。そのため、スマートフォンではログイン前に不要なスクロールが発生する。

フォントについては、`src/app/layout.tsx` が実フォントではなくクラス名を仮変数として設定し、`src/app/globals.css` が未定義の `var(--font-inter)` / `var(--font-geist-mono)` を参照している。生成 CSS にもこの参照が残るため、フォント宣言が無効化される可能性がある。

## 2. 決定事項

### 2.1 画面構成

`/login` 専用の最小フレームにする。`SiteHeader` と `SiteFooter` は表示しない。画面中央にロゴと認証カードを置き、キャッチコピー、デバイス説明、補足カードは削除する。

通常状態のカードは次の要素だけで構成する。

1. 「ログイン」見出し
2. 設定済みの Google / Apple ボタン
3. `Passkey / メールで続行`
4. 「アカウントを作成」テキストリンク
5. 利用規約・プライバシーポリシーの同意文

プロバイダーは `getConfiguredCognitoIdentityProviders()` で有効なものだけ描画する。未設定のプロバイダーを「設定中」として表示しない。Passkey / メールとアカウント作成の導線は維持する。

モバイルは `100svh` と左右 16px 程度の余白を基準にし、320×568 の通常状態でも縦スクロールを発生させない。エラー表示で高さが増える場合は、内容を隠さず自然なスクロールを許可する。デスクトップも同じカードを中央配置し、2カラムにはしない。

### 2.2 フォントと視覚仕様

- 仮のフォントオブジェクトと重複した body のフォントクラスを廃止し、必要な `font-sans` は1つだけ残す
- `--font-sans` と `--font-mono` は未定義 CSS 変数を参照しない具体的なフォールバックスタックにする
- ログインの日本語本文には `font-jp`、見出しには `font-jp-heading` を明示的に適用する
- 既存の YakuHanJP / Zen Kaku Gothic New の仕組みを利用し、新しいフォント依存は追加しない
- ボタンとリンクを含むすべての操作要素のタップ領域は最低 48px とする
- フォーカスリングを維持する
- グラデーションや大きな影は使わず、既存の背景・surface トークンの差で階層を示す

### 2.3 認証契約

Cognito route、セッション、API、認証方式は変更しない。既存の `redirect_uri`、`state`、`code_challenge`、`platform` の引き継ぎも維持する。UI は既存リンクの生成先だけを使う。

エラーはカード上部に表示する。未設定プロバイダーの表示を削除しても、プロバイダー指定時の route 側検証は変更しない。

## 3. 対象範囲

変更対象は次のファイルに限定する。

- `tastile-web/src/app/login/page.tsx`
- `tastile-web/src/app/layout.tsx`
- `tastile-web/src/app/globals.css`
- `tastile-web/src/app/marketing-layout.test.tsx`

`src/app/layout.tsx` と `src/app/globals.css` の変更は、ログイン画面で表面化した全体フォントトークンの修復である。ログイン以外の公開ページのレイアウトは変更せず、フォント修復による回帰だけを確認する。既存の未コミット変更があるため、上記以外のファイルは触らない。

## 4. 検証

- 320×568、390×844、1280×800 で通常状態を確認する
- 通常状態に縦・横スクロールがないことを確認する
- エラー文が切れず、カード内で読めることを確認する
- Google / Apple の設定済み・未設定の表示を確認する
- ネイティブ向けクエリがリンクに残ることを確認する
- 生成 CSS に未定義フォント変数が残っていないことを確認する
- フォント修復後も `/`、`/pricing`、`/download` のレイアウトに回帰がないことを確認する
- `bun run lint`
- `bun run typecheck`
- `bun run test:unit`
- `bun run build`

## 5. ロールバック

実装後に問題があれば、上記4ファイルの変更だけを戻す。認証 route やデータには変更を加えないため、ロールバックにデータ移行は不要。
