## 検証と制約

この作業で実行した入口:

```powershell
bun scripts/check-release-plan.ts
pwsh -NoProfile -File .agent-loop/gate-root.ps1
```

初期planのDAG/closureとroot agent environment gateは終了コード0。GitHub readbackの件数・milestone・labels・依存参照・branch SHAは別の検証記録にまとめる。
Schemaは実効sandboxを生成しない。generation fencing、全repo snapshot照合、独立review、外部writeのjournal照合はdispatch/integrationの必須手順として残る。

製品source、coverage threshold、test exclusion、CI構成、env実値は変更していない。
既存のfull gate、実DB、実browser、署名済みAndroid、配送provider、backup/restore、公開配布は今回未実行であり、各Issueの完了条件。
root gateが通ったことを製品のrelease可能判定として扱わない。
Webの既存check:releaseにはadvisory ignoreが含まれる。R05ではignoreなしの
`bun audit --production`を別途実行し、適用対象の未解決advisoryをrelease blockerとして扱う。

最終の作成内容と検証証跡は[検証記録](2026-09-19-verification.md)を参照する。

release候補の全体入口はquality profileを参照する。PowerShellから複数repoを指定する場合は配列を使う:

```powershell
pwsh -NoProfile -Command "& ./scripts/check-workspace.ps1 -Repository @('core','web','android') -Profile full -KeepGoing -ResultPath .tmp/release-check.json"
```
